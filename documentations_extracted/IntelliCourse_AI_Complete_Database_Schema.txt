Career Readiness / Skill Gap / Next Action

Skill Intelligence evaluates and maintains the student's current skill state.

Career Readiness Engine compares student skills against career requirements.

Skill Gap Engine identifies missing or underdeveloped skills.

Recommendation Engine ranks courses using the weighted recommendation factors.

Next Best Action Engine chooses the most valuable immediate action.

Personalized Roadmap Engine creates a sequence from career requirements, dependencies, current skills, and missing skills.

Assessment results update skill levels, which trigger readiness and recommendation recalculation.

The AI Advisor must use structured student context and must not invent student facts.

19. Indexes & Performance Recommendations

Index users.email.

Index student foreign keys and commonly filtered student-owned records.

Index student_skills by (student_id, skill_id).

Index career_skill_requirements by (career_id, skill_id).

Index course_skills and course_prerequisites foreign keys.

Index recommendations by student, match score, and generated_at.

Index learning records by student, status, and timestamp.

Index analytics by student, event_type, and created_at.

Use Redis caching for expensive/repeated intelligence calculations where appropriate.

Use Celery for background recommendation generation, readiness recalculation, notifications, analytics aggregation, and other non-blocking jobs.

Prefer a single dashboard endpoint to reduce frontend request overhead.

21. Production-Grade Improvements Identified

#

Production Recommendation

1. Django User Model

Use a custom Django User model with email as login. Django normally manages password hashing rather than storing a manually managed application-level password_hash field.

2. Roles & Permissions

Consider Django Groups/Permissions instead of a custom user_roles table unless domain-specific role metadata is required.

3. Student University Redundancy

student_profiles contains university_id while college already points to university. Prefer removing the redundancy unless it is intentionally denormalized for performance and consistency is enforced.

4. Academic History

Add student_academic_records / semester-wise performance tables if historical SGPA, marks, and academic progress are required.

5. Subject-Level Analytics

Add student_subject_performance if the system needs subject-level analytics.

6. Career Classification

Consider career_interests or career-category relations if career discovery needs structured interest mapping.

7. Course–Career Mapping

Consider course_careers if a course directly prepares multiple careers; otherwise derive the relationship through skills.

8. Internal Course Content

Add course_modules / course_lessons only if IntelliCourse will host and track internal content. For external course links, the current courses table is sufficient.

9. Assessment Skill Weights

Add assessment_skill_weights if skill contribution needs weighting beyond question marks.

10. Recommendation Feedback

Add recommendation_feedback for responses such as not interested, already know this, or too difficult; this can improve ranking.

11. Career Readiness History

Add career_readiness_snapshots to persist readiness over time and power improvement/trend charts.

12. Skill Gap History

Add skill_gap_snapshots if historical skill-gap evolution must be visualized or analyzed.

13. Profile Completion

Prefer deriving profile completion dynamically instead of storing redundant completion percentages.

14. Admin Audit Fields

Consider created_by and updated_by on admin-managed master data.

15. Soft Delete / Archive

Use archive/soft-delete fields on content tables when historical references must remain intact.

16. Roadmap Dependencies

Add roadmap_node_dependencies if roadmap nodes need arbitrary dependencies beyond skill prerequisites.

17. Action History

Add student_action_history if every generated/completed/dismissed action must be auditable.

18. AI Observability

Consider storing model, prompt_version, response latency, token usage, and safety flags for AI cost/version monitoring. Avoid storing sensitive prompts unnecessarily.

22. Security Requirements

Password hashing must be handled securely using Django's authentication system.

Use JWT access and refresh tokens where JWT authentication is selected.

Apply role-based permissions.

Enforce student data isolation so a student cannot access another student's records.

Use HTTPS in deployed environments.

Configure CORS and CSRF appropriately for the deployment architecture.

Apply API rate limiting, input validation, and authorization checks.

Store secrets and credentials in secure environment variables/secrets management.

Run production with DEBUG=False.

Protect AI context and student data from unnecessary exposure.

27. Important Implementation Note

The 47-table schema is the baseline logical model. The production-grade improvements listed in Section 21 are recommendations, not silent modifications to that baseline. Before generating Django migrations, PostgreSQL CREATE TABLE scripts, or the final ERD, the project team should decide which improvements are in scope.
