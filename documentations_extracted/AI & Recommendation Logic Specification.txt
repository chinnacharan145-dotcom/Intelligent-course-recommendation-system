IntelliCourse AI — AI & Recommendation Logic Specification

1. Purpose

The AI & Recommendation Logic layer is the intelligence core of IntelliCourse AI.

Its purpose is to continuously understand:

Who the student is 

What the student knows 

What the student wants to become 

What skills are required 

Which skills are missing 

What the student should learn 

What the student should do next 

How the student's career readiness is changing 

The central principle is:

Every important student interaction should produce a meaningful understanding of “What should I do next?”

The Skill Intelligence Engine maintains the student's current skill state.

Each skill should have:

 ├── Proficiency

 ├── Source

 ├── Last Assessed

 └── History

5.2 Proficiency

Proficiency should be represented on a:

5.3 Confidence

Confidence represents how reliable the system believes the proficiency estimate is.

Example:

Python

Proficiency = 65

Confidence = 85

Source = Assessment

This means the student appears reasonably strong in Python and the system has high confidence in that estimate.

7. Skill Gap Engine

7.1 Purpose

The Skill Gap Engine compares:

Required Career Skill

             VS

Student Current Skill

For each career requirement:

Gap = Required Level - Student Proficiency

If:

Gap <= 0

the student has reached the required level.

If:

Gap > 0

the student has a skill gap.

9. Skill Dependency Logic

Skills can have prerequisites.

Example:

Python

   ↓

Statistics

   ↓

Machine Learning

   ↓

Deep Learning

   ↓

AI Projects

   ↓

AI Engineer

If:

Deep Learning = 10

Machine Learning = 30

the system should first determine whether Machine Learning prerequisites are satisfied.

Therefore:

The largest gap is not always the next learning action.

Dependency-aware ordering is mandatory for personalized roadmap generation.

10. Career Readiness Engine

10.1 Purpose

Career readiness represents how prepared the student currently is for a selected career based on the available structured data.

For each required skill:

Skill Achievement =

min(Student Proficiency / Required Level, 1)

The career skill weight determines its contribution.

Conceptually:

Career Readiness =

Σ(Skill Achievement × Skill Weight)

/

Σ(Skill Weight)

× 100

Example:

Skill

Required

Student

Weight

Python

80

70

1.0

Statistics

75

40

0.8

ML

80

30

1.0

The engine calculates a weighted readiness percentage rather than simply averaging raw student scores.

14. Recommendation Score

Conceptually:

Recommendation Score =

(Career Match × 0.30)

+

(Skill Gap × 0.25)

+

(Interest × 0.15)

+

(Branch × 0.10)

+

(Semester × 0.10)

+

(Difficulty × 0.05)

+

(Content Similarity × 0.05)

Every factor should be normalized to:

0–100

The final recommendation score should also be:

0–100

15. Career Match Score

Career Match determines how strongly a course supports the student's target career.

Example:

Target Career = AI Engineer

Course:

"Machine Learning with Python"

Career Match = 95

A course unrelated to the target career may receive:

Career Match = 10

16. Skill Gap Score

The system should give higher priority to courses that address important missing skills.

Example:

Student:

Python       75

Statistics   40

ML           30

A Machine Learning course should receive a strong Skill Gap score because it addresses an important deficiency.

17. Interest Score

The system should compare course topics/categories against student interests.

Example:

Student Interest:

Artificial Intelligence = High

Course:

Deep Learning

Interest Score = High

This improves personalization without making interest the dominant factor.

18. Branch Match Score

Branch relevance should be considered.

Example:

Student Branch = CSE

Course = Advanced Python Programming

Branch Match = High

The same course might have a lower branch relevance for a student whose academic background is unrelated.

19. Semester Match Score

Recommendations should consider the student's academic stage.

For example:

Semester 2:

Programming Fundamentals

Semester 4:

Data Structures / DBMS

Semester 6:

Machine Learning / Cloud / Advanced Development

The engine should avoid repeatedly recommending content that is significantly inappropriate for the student's current academic stage.

20. Difficulty Match

Difficulty should be compared with the student's current level.

Example:

Student Skill = Beginner

Course Difficulty = Advanced

This should reduce the difficulty-match component unless the student has prerequisites or the recommendation is intentionally designed as a stretch goal.

21. Content Similarity

Content similarity can compare:

Course skills 

Course category 

Course description 

Previously completed courses 

Previously accepted recommendations 

Current learning interests 

This component should remain relatively low-weighted in the baseline model:

5%

so that similarity does not overpower career and skill-gap requirements.

22. Recommendation Eligibility Filtering

Before calculating ranking, courses should pass eligibility checks.

Example filters:

Course is active

        ↓

Not already completed

        ↓

Not already dropped repeatedly

        ↓

Prerequisites satisfied

        ↓

Relevant to target career / skill gap

        ↓

Suitable difficulty

        ↓

Eligible candidate

The system should avoid recommending a course that the student has already completed unless there is a deliberate refresher rule.

32. AI Advisor

It should not replace the recommendation engine.

34. AI Advisor Grounding Rule

The most important AI rule is:

The AI Advisor must never invent student facts.

For example, if the database does not contain:

Student completed an internship at Google

the AI must not claim:

"You completed your Google internship..."

Instead:

"I don't have information about an internship in your current profile."

43. Intelligence Quality Principles

The system should optimize for:

Relevance

Recommendations must relate to the student's actual goal.

Explainability

The student should understand why something was recommended.

Personalization

Two students should not necessarily receive identical recommendations.

Dependency Awareness

Prerequisites must be considered.

Recency

Recent assessments and activity should influence current state.

Consistency

The same input should produce stable results unless underlying data changes.

Actionability

The system should tell students what to do, not merely show information.

48. Future ML Evolution

The initial IntelliCourse AI implementation should use deterministic, explainable scoring.

Later, the recommendation system can evolve toward:

Rule-Based Ranking

        ↓

Weighted Recommendation

        ↓

Behavior-Aware Ranking

        ↓

Machine Learning Ranking

        ↓

Hybrid Recommendation System

Potential future approaches include:

Learning-to-rank 

Embedding-based similarity 

Collaborative filtering 

Content-based recommendation 

Hybrid recommendation 

Reinforcement-style next-action optimization 

However:

ML should improve the recommendation system without making the system impossible to explain.
